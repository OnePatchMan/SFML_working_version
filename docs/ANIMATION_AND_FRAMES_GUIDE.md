## 1. Анатомия боевого удара (Fighting Game Frame Data)

В файтингах единицей измерения времени является **1 игровой кадр при 60 FPS**:

$$\text{1 кадр (Frame)} = \frac{1}{60} \text{ секунды} \approx 0.01667 \text{ с} \approx 16.67 \text{ миллисекунд}$$

Каждый удар состоит из трех непрерывных фаз:

```
[ Нажатие кнопки ]
       │
       ▼
┌──────────────────┐   ┌────────────────────────┐   ┌────────────────────────┐
│     STARTUP      │ ─►│         ACTIVE         │ ─►│        RECOVERY        │
│  (Замах / Кадры  │   │  (Активные кадры удара │   │    (Восстановление /   │
│   подготовки)    │   │   и включения хитбокса)│   │   возврат в стойку)    │
└──────────────────┘   └────────────────────────┘   └────────────────────────┘
```

1. **Startup (Подготовка / Замах)**:
   * От нажатия кнопки до 1-го кадра урона. В текущей версии движка удары мгновенно активируют хитбокс на 1-м кадре ($\text{Startup} \approx 0\dots 1$ кадр) для бескомпромиссной отзывчивости ввода.
2. **Active (Активные кадры / Удар)**:
   * Время жизни хитбокса в мире (`active_time` в `combat_balance.kv`).
   * Формула пересчета: $\text{Кадры} = \text{round}(\text{active\_time} \times 60)$.
3. **Recovery (Восстановление)**:
   * Время возврата в нейтральную стойку после отключения хитбокса (`player_recovery`). При промахе по воздуху действует штраф уязвимости `whiff_stun`.
   * Формула пересчета: $\text{Кадры} = \text{round}(\text{player\_recovery} \times 60)$.

## 3. Архитектурный разбор: Влияние частоты кадров (FPS) на физику и тайминги

Движок поддерживает неограниченную частоту кадров (до 1500+ FPS благодаря GPU-кэшированию освещения и пакетной отрисовке VertexArray):
```cpp
float dt = dtClock.restart().asSeconds();
if (dt > 0.1f) dt = 0.1f; // Clamp от зависаний
```

### 3.1. Тайминги атак и анимации (`Animator.cpp`, `CombatSystem.cpp`)
* **Полная независимость от FPS**: таймеры активных кадров, восстановления и кулдаунов декрементируются реальным `dt`:
  $$\text{attackTimer} -= dt$$
* Любой прием длится ровно заданное число секунд вне зависимости от того, работает игра на 60 FPS, 144 FPS или 1500 FPS.

### 3.2. Численное интегрирование физики (Эйлер)
* **Формулы движения**:
  ```cpp
  velocity.y += gravity * dt;
  position += velocity * dt;
  ```
* При разной частоте кадров накапливаемая погрешность пика прыжка составляет менее 1–2 пикселей.
* Для строгого детерминизма повторов и сетевой синхронизации (Rollback Netcode) физические шаги рекомендуется квантовать с фиксированным шагом $1/60$ с (Fixed Timestep Accumulator).
